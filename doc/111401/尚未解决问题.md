本轮审查发现的跨文档实质冲突和不完整客户端算法已修复，当前未发现需要先由用户裁决才能继续的产品或技术选项。四份文档可作为后续实施依据。

## 已明确接受的第一版限制

| 限制 | 影响与既定处理 |
|---|---|
| 原始输出截断不可恢复已丢信息 | 重建xterm清除旧画面、滚动历史及解析状态后，仅回放保留后缀；后缀可能从UTF-8/ANSI中间开始，仍可能出现残片、颜色/光标差异，不能保证恢复vim/top完整屏幕。终端外提示截断；不引入服务端终端模拟器。 |
| 持续输出超过浏览器处理能力 | 单通道只回放一次；缺口结束通道，有限次数重新绑定。持续过载可能最终停止自动恢复，需要用户检查环境后主动操作。 |
| 输入没有端到端确认/撤回能力 | 已准入SSH调用可能在普通断开后产生效果；队列中尚未准入的旧操作丢弃。未发送/不确定输入不自动重发，避免重复命令。接管在同一操作串行门之后提交。 |
| 绑定提交成功但响应丢失 | 原凭证已消费；客户端保留旧代次可能得到冲突并停止，由用户刷新状态并主动操作。不会盲目采用新代次抢回。 |
| 关闭通知及末尾输出尽力送达 | SSH关闭不等待所有缓存输出送完；客户端有限排空已经接受的数据。网络丢失时通过HTTP状态确认，不能承诺尾输出完整。 |
| 进程重启不恢复SSH | Session、缓存、probe及绑定凭证丢失；数据库仅留元数据，启动清理后不展示为活动。既有产品范围不变。 |
| 总内存不是固定常量 | 单Session和单WS资源有界，但总量随实际服务器和活动Session数量增加；实施时按核心限额与架构公式评估，不能宣称无限Session仍固定内存。 |
