| P1：协议 P1-7 | HTTP 升级前原子预占全局 WS 名额；覆盖升级、未绑定、当前和关闭中通道。快照、实时块、控制项、输入项和前端队列分别有界，不把单缓存有界误称为全进程固定内存。 | 核心配置；架构 §7/§10；协议 §5/§7；阶段连接容量及稳定性验收。 |

## 修订过程中额外收口的边界

| 问题 | 已修复结果 | 证据/位置 |
|---|---|---|
| 浏览器主动 close 误用服务端保留码 | 客户端过载使用4003；服务端OUTPUT_GAP为4002、taken_over为4001。 | 协议 §4.4及参考协调器；模拟场景13。 |
| 正常大粘贴被容量1槽立即拒绝 | Reader有界等待空位；超时INPUT_BACKPRESSURE停止恢复且不重放输入，SSH读取独立。 | 架构 §6、协议 §4.1、阶段3大粘贴测试。 |
| 默认恢复预算先于正常心跳判离线耗尽 | 默认预算在核心设为10次、间隔5秒；模拟40秒后解除旧绑定可恢复，仍保留有限失败边界。 | 核心 §7；模拟场景15。 |
| 稳定资格被连续HTTP失败反复消费 | consumeStability一次性清除资格，不能无限重置预算。 | 协议 §6–7；模拟场景20；阶段4重试预算测试。 |
| 终端视图缺少最终销毁入口 | stop保留实例；dispose幂等停止网络、有限排空、移除监听并销毁，销毁超时不创建无用实例，迟到回调失效。 | 协议 §6–7；模拟场景16–19；阶段4视图销毁测试。 |
| Close后的旧Detach可能回退状态 | Close在锁内撤权并清当前Binding，仅另存通知引用；Detach只有当前绑定且CONNECTED才转DISCONNECTED，关闭态不回退。 | 架构 §4.2–4.3；协议时序表；阶段4统一关闭验收。 |
| 核心要求自动先查询新代次而协调器未执行 | 去掉额外强制查询；绑定结果不明仍按原代次有限恢复，冲突后由用户主动处理。 | 核心 §11.4与协议 §7一致。 |
| 回收及交易细节仍可能产生竞态 | 明确资源迟到登记、SSH/WS等待组隔离、计数溢出后锁外Close、probe事务占用防清理、登录撤销防晚发布、元数据最终写入独立上下文。 | 架构 §3–4/§7–10；阶段故障与并发测试。 |
